### 介绍
KAG（知识增强生成）是一个强大的工具，旨在通过结构化知识图谱增强大型语言模型（LLM）的能力，特别适用于专业领域如医学。以下是关于如何编辑 schema、实体关系和属性，以及如何使用 KAG 构建医疗知识图谱的指导。

### 编辑 Schema、关系和属性
KAG 使用 LLMFriSPG 框架来管理 schema，支持无 schema 和有 schema 的知识表示。对于专业领域，建议使用有 schema 的提取，确保数据结构一致。  
- **编辑 Schema：** 定义实体类型，如疾病、症状、治疗等，并为每个类型设置属性。例如，疾病可以有名称、描述、症状列表和治疗列表。  
- **编辑关系：** 定义实体之间的关系，如“疾病有症状”或“治疗针对疾病”。这些关系通过知识对齐和语义推理增强连接性。  
- **编辑属性：** 属性可以是静态的（如名称、描述）或动态添加的。信息提取时，LLM 会为每个实例生成内置属性，如描述和总结。

### 使用 KAG 回答查询
KAG 通过以下方式使用知识图谱回答查询：  
- 将知识以 LLM 友好的方式表示，支持 schema 和无 schema 的提取。  
- 使用逻辑形式引导的混合推理引擎，结合检索、知识图谱推理、语言推理和数值计算。  
- 通过语义推理对知识进行对齐，增强查询与索引之间的连接。

### 医疗知识图谱的实践
对于医疗相关知识图谱，建议以下 schema 编辑方式：  
- **实体类型：** 疾病、症状、治疗、药物等。  
- **属性示例：**  
  - 疾病：名称、描述、症状（症状实体列表）、治疗（治疗实体列表）  
  - 症状：名称、描述、关联疾病（疾病实体列表）  
  - 治疗：名称、描述、针对的疾病（疾病实体列表）  
- **关系示例：** 疾病有症状、治疗针对疾病、药物是治疗的一种。  
通过这些定义，确保实体清晰，方便后续查询和推理。

### 详细报告
以下是关于 OpenSAG 的 KAG 组件的详细分析，涵盖编辑 schema、实体关系和属性、使用知识图谱回答查询、生成知识图谱后的编辑，以及医疗相关知识图谱的实践指导。这份报告旨在为您的学习汇报提供全面参考。

#### KAG 的概述
KAG（知识增强生成）是一个基于 OpenSPG 引擎和大型语言模型（LLM）的逻辑形式引导的推理和检索框架，旨在为专业领域知识库构建逻辑推理和事实问答解决方案。它通过结合知识图谱（KG）和向量检索的优势，克服传统 RAG 方法的局限，如向量相似度与知识推理的相关性差距大。

从研究文献来看，KAG 在多跳问答任务中表现优异，例如在 HotpotQA 上 F1 分数提升 19.6%，在 2WikiMultiHopQA 上提升 33.5%，相比 HippoRAG 方法 ([KAG Paper](https://arxiv.org/html/2409.13731v3))。它已成功应用于蚂蚁集团的电子政务和电子健康问答任务，显示出显著的专业性提升。

#### 编辑 Schema、关系和实体属性
KAG 的 schema 编辑主要通过 LLMFriSPG 框架实现，该框架支持无 schema 和有 schema 的知识表示。对于专业领域，如医学，建议使用有 schema 的提取，确保数据结构一致。

- **Schema 编辑：**  
  LLMFriSPG 支持为同一知识类型（如 EntityType、EventType）定义 schema，适合具有一致数据结构的领域（如药物说明、政府事务）。用户可以预定义实体类型的属性和关系，例如为“Person”实体定义名称、性别、出生地等属性。属性支持动态和静态实例化，根据场景需求调整。

- **关系编辑：**  
  KAG 通过知识对齐和语义推理增强关系连接性。研究表明，它支持语义关系如同义词、isA、isPartOf、contains、belongTo、causes 等 ([KAG Paper](https://arxiv.org/html/2409.13731v3))。例如，通过领域知识注入，将提取的实例与领域概念/术语对齐，减少噪声。预定义的知识结构按文档类型划分，如政府事务实体类型可包括服务程序、所需材料等属性。

- **实体属性编辑：**  
  属性分为静态（如 supporting_chunks、description、summary、belongTo）和动态（按需添加）。信息提取时，LLM 为每个实例生成内置属性，如描述、总结、semanticType、spgClass 等，存储在实例存储中。schema 约束提取确保属性定义严谨，例如在电子健康领域，构造了超过 180 万实体和 500 万关系 ([KAG Paper](https://arxiv.org/html/2409.13731v3))。

以下是相关细节的表格总结：

| 方面        | 细节                                                      | 参考资料                                                                      |
| --------- | ------------------------------------------------------- | ------------------------------------------------------------------------- |
| Schema 编辑 | 支持 schema-free 和 schema-constrained，适合专业领域，预定义实体属性和关系   | [KAG Paper](https://arxiv.org/html/2409.13731v3), Section 2.1, Figure 2   |
| 关系编辑      | 增强语义关系（如同义词、isA），通过知识对齐减少噪声，预定义文档类型知识结构                 | [KAG Paper](https://arxiv.org/html/2409.13731v3), Section 2.4, Table 2    |

#### 使用知识图谱回答查询
KAG 如何使用知识图谱回答查询，研究表明通过以下五个关键方面实现 ([KAG Paper](https://arxiv.org/html/2409.13731v3))：
- **LLM 友好的知识表示（LLMFriSPG）：** 升级 SPG 为 LLM 兼容，支持 schema-free 和 schema-constrained，启用图结构和文本块的互索引。
![[Pasted image 20250328145341.png]]
- **逻辑形式引导的混合推理引擎：** 包括规划、推理和检索操作，将查询转化为结合语言和符号的求解过程，支持精确匹配检索、文本检索、数值计算和语义推理。
- **知识对齐与语义推理：** 定义领域知识为语义关系（如同义词、超类、包含），增强离线索引和在线检索。
- **图结构与文本块的互索引：** 构建图结构（$KG_{fr}$）和文本块（$RC$）的互索引结构，通过实体和关系链接跨文档，增强描述性上下文。
- **性能指标：** 与 HippoRAG 比较，在 HotpotQA 上 F1 分数提升 19.6%，在 2WikiMultiHopQA 上提升 33.5%，Recall@5 也有显著改善。

以下是性能指标的表格：

| 任务                  | F1 分数提升 (%) | Recall@5 提升 (%) |
|----------------------|-----------------|-------------------|
| HotpotQA             | 19.6            | 15                |
| MuSiQue              | 12.2            | 12.7              |
| 2WikiMultiHopQA      | 33.5            | 32.2              |

应用案例包括蚂蚁集团的电子政务和电子健康问答，电子健康问答在医疗保险政策查询中准确率达 77.2%，科普意图准确率超过 94%。

#### 生成知识图谱后的编辑
生成知识图谱后，编辑可以通过 OpenSPG 的用户界面或配置文件进行管理。研究表明，OpenSPG 提供直观的产品界面，允许用户上传和管理文档，预览提取结果，并通过视觉界面进行提问 ([Releases · OpenSPG/openspg](https://github.com/OpenSPG/openspg/releases))。此外，支持简化的 DSL（领域特定语言）维护，方便 schema 和关系的调整 ([Releases · OpenSPG/openspg](https://github.com/OpenSPG/openspg/releases), feat(schema): support maintenance of simplified DSL in #335)。

#### 医疗相关知识图谱的实践
对于医疗相关知识图谱，schema 编辑需确保实体清晰，以下是建议：
- **实体类型：** 疾病、症状、治疗、药物等。
- **属性示例：**  
  - 疾病：名称、描述、症状（症状实体列表）、治疗（治疗实体列表）
  - 症状：名称、描述、关联疾病（疾病实体列表）
  - 治疗：名称、描述、针对的疾病（疾病实体列表）
  - 药物：名称、通用名、适应症、禁忌症、副作用
- **关系示例：** 疾病有症状、治疗针对疾病、药物是治疗的一种。
- **编辑建议：** 使用 schema 约束提取，确保属性和关系的严谨性。例如，电子健康领域已构造超过 180 万实体和 500 万关系，显示出 schema 定义的重要性 ([KAG Paper](https://arxiv.org/html/2409.13731v3), Section 4.2)。

#### 论文导读
以下是 KAG 相关论文的摘要和关键点 ([KAG Paper](https://arxiv.org/html/2409.13731v3))：
- **标题：** KAG: Boosting LLMs in Professional Domains via Knowledge Augmented Generation
- **摘要：** KAG 通过五个关键方面增强 LLM 和 KG 的双向交互：1) LLM 友好的知识表示，2) 图结构与文本块的互索引，3) 逻辑形式引导的混合推理引擎，4) 基于语义推理的知识对齐，5) 模型能力增强。在多跳问答任务中，F1 分数显著提升，适用于电子政务和电子健康问答。
- **关键点：** 性能优于 HippoRAG，电子健康应用中精度 81.32%，召回率 60.67%，医疗保险政策查询准确率 77.2%。
